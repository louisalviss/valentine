The core idea

Compatibility isn't a plugin property. It's a stack property.

A plugin can look healthy in isolation and still fail when versions, PHP, HPOS, Checkout Blocks and another extension meet in one store. Preflight treats every update as an edge in a changing compatibility graph.
01 / Observe

Watch real transitions.

Opt-in telemetry records version changes and technical outcomes without turning the store into a public fingerprint.

02 / Compare

Find your nearest stacks.

Risk comes from environments that resemble yours—not from a generic “compatible” badge attached to one plugin.

03 / Warn

Flag risky edges early.

Surface sparse evidence, failure clusters and environment mismatches before an update is approved.

FAQ

Questions before install.

Is this another staging or rollback tool?

No. The concept is pre-update intelligence. Staging and rollback tools help after you decide to test or deploy; Preflight is meant to improve that decision first.

Does this demo show real failure rates?

No. All graph and report states on this page are explicitly illustrative. A production product should display only evidence-backed observations with dates, versions and confidence.

Why focus on WooCommerce first?

Because checkout, payments, subscriptions and operational extensions create dense dependencies where version combinations matter. A narrow ecosystem also makes the compatibility graph more useful than a shallow all-WordPress index.
